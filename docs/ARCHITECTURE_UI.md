# 架构、隐私、多端页面与阶段验收

状态：P0架构与交互评审草案。以下是拟建方案，不代表应用、工作流、主机或站点已经存在。

## 1. 最小技术栈与取舍

| 层 | 建议 | 理由与边界 |
|---|---|---|
| 采集/计算 | Python、显式来源适配器、Decimal；pytest或标准库单测 | 数据字段和研究公式易审计；开源采集库可作适配器但必须追溯上游，不能依赖一个黑箱函数完成全部研究 |
| 历史层 | 单写者DuckDB + 分区Parquet，原始合法留存响应另存 | 适合个人日频离线分析；无需常驻数据库服务。原始证据、标准层和修订记录不同目录，不能只留最后一次结果 |
| 运行 | 经核实的自托管Linux主机；定时器/Actions为触发方式 | 优先复用硬件，不预设runner已配置。不靠临时Actions磁盘或缓存作唯一历史数据库 |
| 导出 | 字段白名单的静态JSON + 内容哈希manifest | 只导出获准公开的衍生结果，按日/行业按需加载，避免浏览器调用密钥API |
| 前端 | Vue 3 + TypeScript + Vite；ECharts按需加载 | 单页研究工作台，标准浏览器能力；最终依赖版本在P1查维护状态并锁定，不把P0提议当已验兼容性 |
| 测试 | 数据单测/契约测；Playwright Chromium/WebKit + 人工实机 | 浏览器自动化与真机分别验收，WebKit模拟不等于iPad Safari实测 |
| 发布 | GitHub Pages，仅静态公开产物 | 不承担数据采集、保密API、数据库或私有账户同步 |

不引入微服务、Kubernetes、实时消息总线、常驻大模型和自动交易。P0复算脚本只用标准库，以上生产依赖尚未安装到项目。未来报告优先模板化；若引入LLM，数值和信号仍来自确定性计算，模型只解释有证据的数据，不能编造缺失字段。

## 2. 数据与信任边界

```text
官方/获授权数据源
    ↓ 有限频率获取、记录真正获取时刻
[私人采集区] 原始响应/版本 → 校验/隔离 → 标准化历史
    ↓ 单写者事务 + 不可变历史分区
[私人研究区] PIT快照 → 指标 → 条件观察 → 报告revision
    ↓ 权限审查 + 字段白名单 + 敏感信息检查
[发布暂存区] 固定data_version的一致JSON/manifest/前端资产
    ↓ 构建核验成功后完整部署
[公开Pages] 只读静态工作台
    ↕ 浏览器本地自选/备注（不上传，不宣称同步或绝对安全）
```

采集区可以有上游凭据，发布区不能收到上游凭据或个人投资信息。自托管runner不可执行不受信任fork/PR代码并同时拥有机密；测试与可写部署凭据权限分离。部署令牌最小范围，日志脱敏，无第三方分析脚本和自动外传备注。

合法原始响应按来源/日期/获取批次保存；其保留期限、备份和访问权限遵守来源授权。定期备份必须在主机之外保有可恢复副本（保存地点/费用另核实），测试恢复。源码Git只存代码、规范、小型固定测试样例；原始日行情与长期历史不逐日提交主分支。

## 3. Pages、账户与成本的实测边界

仓库元数据为private且has_pages=false。本轮未部署，未更改可见性。profile不提供套餐；Pages管理与runner管理路径被当前连接器限制，因此套餐、额度和runner可用性仍未知，不以“不存在”代替“不能读取”。

[GitHub Pages文档](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)：静态服务；Free支持公共仓库，私有仓库使用Pages需要支持该能力的付费套餐。私有源码不保证站点私有。私人投资信息不能因为仓库private就进入产物。

[Actions计费文档](https://docs.github.com/en/actions/concepts/billing-and-usage)当前说明自托管runner的Actions使用免费；自有硬件、电力、备份和运维仍有成本。私有仓库的托管runner额度与账户计划有关，超额可收费。本轮未核实剩余额度，不启动可能收费的任务；“当前规则”不承诺永久免费。

决策分支：账户已有适用套餐且数据发布获准，则评审从ql发布静态站；若套餐不适用，保持ql私有，可另评审单独公共发布仓库或其他静态承载，不自动公开源码/数据或购买套餐。

[Vite静态部署文档](https://vite.dev/guide/static-deploy.html)要求项目子路径配置正确。拟用Pages项目路径时设置base=`/ql/`，优先hash路由避免静态站深链接刷新404；自定义域根路径再独立配置。页面真实URL未建立，不提供假上线链接。

## 4. 版本、一致发布、缓存与回滚

产物manifest包含：schema_version、data_version、method_version、code_commit、universe/calendar_version、trade_date、report_revision、generated_at、各来源asof、质量状态、许可审查版本、文件哈希/大小。

前端启动时读取一次manifest并固定该版本，再读取带内容哈希的数据分块。页面上的所有图表必须来自同一报告版本，不能市场卡片今天、资金图昨天却无标注。各维度允许合法不同截至日，但须逐项展示，且不得据此生成伪同日共振。

不依赖随意设置Pages自定义缓存头；内容哈希路径和schema兼容性是主要一致性手段。发布包保留当前及至少上一有效数据/接口版本，旧页面取不到旧块时显示“版本已更新，请刷新”，不能混拼。构建/权限/质量检查失败保留上一部署，并依据manifest时效显示陈旧；部署后检查子路径、manifest哈希、数据日期和主要链接。

回滚恢复整套前端+数据版本，而不只覆盖某个JSON；历史报告不删除，修订以新revision追加。定稿的含义是“该版必需输入完整”，不是数据永不修订。

## 5. 收盘后运行与任务失效恢复

时区固定Asia/Shanghai，内部可用UTC保存instant但市场日期不能从服务器本地日历猜测。每次运行先读取交易日历，节假日不生成假交易报告；国庆等跨多天休市后的前一交易日不能简单减一天。

报告状态流：`scheduled → collecting → preliminary → final`；获取失败可形成`partial/error`，后续重试补齐；历史修订生成新的报告版本。当天收盘后先提供已完成价格/量价初报，不把需求改成只在次日发报；ETF/融资迟到时保留缺口并追加定稿。具体钟点先连续观察实际可用时刻，再给目标，不承诺某时全部数据必齐。

[GitHub schedule文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)说明排队可能延迟甚至丢失，定时事件在默认分支运行。当前文档已允许IANA timezone，不能沿用“只能UTC”的过时假设。P1采用Asia/Shanghai显式时区或等价的经过测试的UTC转换；本轮不创建定时任务。

幂等键建议`source + trade_date + instrument_scope + revision`；同一天补跑不能重复累计净流量。设置单写者锁、任务超时、限流、指数退避、有限重试、错误分类、缺口账本、断点续采、人工触发和区间补跑。来源404/空表、认证失败、页面结构变化分开，不无限重试或伪造空数据成功。

“任务根本没运行”不能只由那个任务自己检测。主机外或独立触发的watchdog检查心跳与数据截至日；其运行位置、告警通道、费用待确认。P1先提供可人工查询的运行日志，通知通道不默认绑定私人邮箱/账户。Actions缓存只作加速，不作状态真源。

## 6. 五个页面的信息架构

统一规则：屏幕上方始终可见交易日、报告状态、数据截至日/缺口和观察池范围；“事实/估算/研究”分层表达。点击重要结论可看来源、公式、输入和历史版本。不是只显示一个无法解释的总分。

### 6.1 市场总览（桌面草案）

```text
ql | 总览 行业 标的 自选/复盘 数据/方法 | 2026-10-15 | 评审样例
范围：3只ETF净值；不是全市场        价格可复算 / 资金缺失
今日变化：两只专题产品弱于宽基ETF参照（未复权净值） [证据]
[市场趋势：未启用] [资金：缺连续份额] [广度：未取得成分行情]
[三只ETF归一化净值图：同时间轴、同纵轴] [数据质量与待观察条件]
最近观察及版本变化                                    [查看复盘]
```

生产首页通过主要指数/广度等数据补齐市场背景；P0不能用三只产品替代全市场。初报和陈旧状态不只用小角标隐藏，应有明确句子。

### 6.2 行业轮动

顶部切换“正式行业 / 主题 / 宽基”，5/20/60窗口、分类版本、覆盖门槛。主体为时间热力图、排名轨迹、资金强度与RS散点；不能重复加总主题与行业。散点任一轴缺失则不造点；P0该图应处于禁用状态并解释所缺字段。

点击行进入详情；触屏点击图点固定提示，支持关闭、前后日期、表格替代。提供原值与单位而不只着色。显示净流入额和相对规模强度，不让大ETF仅因体量大永久靠前。禁止用桑基图声称已观察到行业间同一笔资金迁移。

### 6.3 行业/标的详情

```text
产品/行业名称 [分类与覆盖说明] [加自选]
状态：价格偏弱观察；资金证据不足    日期/版本
价格 / ETF份额 / 申赎估值 / 融资 / 广度（各卡独立质量）
共用时间选择器 → 纵向对齐的小图（不用误导双轴）
支持证据 | 反向证据 | 未取得证据
观察条件：何时升级、何时失效     来源与公式/历史版本
```

行业子页只有可靠历史映射才显示成分、头部贡献及宽度，主题页明确包含多行业。个股/ETF可研究但不输出自动下单按钮。

### 6.4 自选与复盘

分组自选、观察理由、时间、条件、失效/兑现状态；保留当时生成的结论，标记后续修订。浏览器本地保存并支持导出/导入及清空确认；跨设备没有自动同步，清缓存/私密模式可能不持久。备注默认纯文本，避免HTML注入；未知第三方脚本不加载。公开产物不含持仓、成本、交易记录和个人备注。

### 6.5 数据与方法

来源ID、字段/单位、原始统计日期、获取时间、首次见到时间、修订、许可状态、数量/AUM覆盖、失败/陈旧原因、方法版本与输入下载权限。权限不允许就只给适当来源指引/定义，不暴露原始批量文件。方法页面解释ETF流≠机构净买、缺失≠零和回测尚未验证。

## 7. 手机和平板交互

手机草案：`顶栏日期/质量 → 一句话变化 → 关键状态卡 → 一个主图 → 可折叠证据 → 底部五入口`。桌面大表不等比缩小：手机优先卡片摘要，点开详细列；复杂表可在自身容器横滑，但整页不溢出。平板根据实际CSS视口变成双栏或单栏，分屏和横竖屏不重新假设物理设备型号。

建议布局断点是设计初值：小于600px单栏，600–1023px可用双栏，1024px以上桌面；须由真实交互测试修正，不根据X500 Pro Max物理分辨率写死。触控目标至少44CSS px，关键操作无需hover，图表拖动与纵向滚动分区，提供显式时间窗口按钮和重置。键盘可达、焦点可见、图表有文字/表格替代，涨跌同时用正负号和文字，颜色不是唯一信息。

计划测试视口360/390/430/768/820/1024/1440px与横屏/分屏；这不是上述设备的已确认viewport。实际vivo机型上的浏览器版本、CSS尺寸、DPR、触控/字体缩放及省电限制必须实测，不能用模拟器冒充验收。

必须覆盖加载、无数据、真零、陈旧、部分失败、证据不足和修订通知。数据多时按行业/日期分块，图表懒加载和行虚拟化；无P0性能测试，P1先记录中档手机首屏和交互基线再确定预算，不预填未经测试的毫秒承诺。

## 8. 阶段任务与放行条件

| 阶段/任务 | 依赖 | 验收证据/失败处理 |
|---|---|---|
| P0-A 接入验证 | 合规访问官方来源、可用运行环境 | 沪深各至少一只ETF相邻交易日份额+同日NAV+权益事件核对；保存来源响应和可复算金额；失败不得用NAV趋势替代 |
| P0-B 数据规范/许可 | 份额字段语义与分类授权 | 历史范围/缺口清单、有效期映射、来源登记与允许导出字段；缺授权则公开功能仍阻塞 |
| P0-C 部署可行性 | 账户套餐、runner、存储/备份可用 | 核实Pages资格与预算、密钥边界、回滚路径；不自动购买资源 |
| P1-A 小范围数据闭环 | P0评审通过 | 日期/单位/重复/缺失/拆分/修订测试；任务幂等、补跑、事务与覆盖率；样例反算一致 |
| P1-B 研究与报告 | 有可用窗口、来源时间一致 | 5日指标先开，20/60日不足禁用；初报当天形成，迟到补齐留版；至少10交易日工程运行初验 |
| P1-C 响应式工作台 | 真实数据契约 | Chromium/WebKit交互、触屏/键盘、子路径刷新、manifest一致、缺失/陈旧/失败状态、图表逐点对账 |
| P1-D 发布 | 明确许可、隐私和账户审批 | 敏感信息扫描、发布后校验、失败保留旧版、回滚演练；未准入数据不进入公开JSON |
| P2 扩展与验证 | 合规长历史、当时分类与权重 | 多市场阶段样本外/简单基线比较、成本与可执行性、误报漏报；统计不足不宣称有效 |
| P3 个人工作流 | 产品评审 | 本地自选/条件记录/复盘；同步、提醒通道与私有持仓单独设计与授权 |

本轮不执行上表的生产开发、定时运行和发布。P0交付的是可维护评审依据、真实价格维度样例及离线防错测试；不是有完整数据的资金监测MVP。
