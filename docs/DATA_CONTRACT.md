# 数据源、时间口径与质量准入

核验日：2026-10-15。下列状态针对本轮实际验证，不断言来源永久可用或不可用。技术入口与公开展示许可分开审批；第三方库开源许可不授予上游金融数据许可。

## 3. 数据契约与双时间模型

推荐历史层主键：`instrument_id + measure + trade_date + source_id + revision_id`。产品映射包含基金主代码、上市交易所、管理人、跟踪指数、类型、生效/终止日期；尚未验证字段明确为空。

| 字段组 | 必须记录的意义 |
|---|---|
| 业务时点 | trade_date、period_start/end、asof_date、effective_from/to：数据属于何时 |
| 信息时点 | source_published_at、fetch_started_at、fetch_completed_at、first_seen_at：何时公布、何时真正得到 |
| 修订 | source_revision、revision_id、supersedes、revision_reason；保留旧行，不覆盖旧事实 |
| 来源 | source_id、exact_url、field_name、raw_unit、normalized_unit、合法可留存响应的hash和location |
| 方法 | data_version、method_version、code_commit、universe_version、calendar_version |
| 数据质量 | status、reason_codes、coverage_count、coverage_aum、observed_source_dates |
| 权限 | allowed_internal_use、allowed_public_raw、allowed_public_derived、expiry、review_reference |

原始数值保留字符串，标准层用Decimal/定点数；展示时才四舍五入。金额统一元，份额统一份，收益百分比与百分点分别编码。不把股份、份额、手混算。

历史回放要求只使用 `first_seen_at <= decision_cutoff` 且当时生效的版本。来源公布时间即使更早，也不能证明系统当时已采集。现在下载的历史行如果没有可靠历史发布时间，只能用于“按已知规则保守延迟的研究假设”，必须标注假设；不能伪造历史实盘可得性。P0摘录将原始发布时间和历史首次可用时刻留空，不倒填。

源站/检索缓存的获取时间不同于数据时点。来源返回旧值时记录实际日期与陈旧状态，不自动覆盖为请求日期。后续重算报告使用新revision，不静默改旧判断。

## 4. 缺失与质量门槛

状态至少包含 observed、estimated、not_yet_published、unavailable、not_applicable、error、quarantined、stale。值为0只能表示可靠观测/计算得到0。没有发布时刻证据时，不随意把获取失败归类成“尚未披露”。

单标的净申赎计算必须同时满足：相邻**交易日**完整份额、明确同日NAV、币种/单位明确、份额折算和异常事件处理通过、来源字段语义对账。缺一个则金额为空。对异常跳变进行人工/事件核查，不裁剪后当正常流量。

滚动h个交易日通常需要h+1个余额/净值观察值；缺中间日不得跨日伪装单日流。产品新上市、清盘、停牌、代码变更和成分生效日必须显式处理，不无条件前向填充。

覆盖率同时提供数量和规模口径。分母需有可核验观察池清单/期初AUM；分母未知则覆盖率未知。不能把3只样例均有NAV显示成“全市场覆盖率100%”。

建议首个很小观察池采用100%必需字段通过才允许资金横向比较；未来扩展可研究95%期初AUM及90%数量门槛，但只是待校准工程阈值，须固定版本、披露未覆盖项。无行业ETF或期初规模过小的桶显示“不可比”，不自动排末位。缺维度时不秘密重新配权。

## 5. 行业映射建议

优先评审中证二级行业作为统一研究口径；以一级显示总览，二级比较轮动，三级仅做钻取。此选择是设计提议，依赖历史归属和授权，不是已经落库。无法取得合规历史分类时，只开放“产品/主题观察”，暂停正式行业排名。

同一指数多个ETF可聚合份额估值变化，但联接基金不重复计数；同一ETF只进入一个互斥统计分区。跨行业主题先单列。后续按成分权重拆分时使用当时已知且有效的权重；同一流量不能既计主题合计又计行业合计后相加。

宽基单列，不把科创/创业板等直接当作半导体或新能源。股价变化导致的持仓权重漂移与份额申赎变化分开；ETF换仓/套利并不等于底层公司同额新增融资，更不识别最终资金所有人。
